# 마고 학원운영 · 1차 시험판

원장·선생님이 오늘 수업, 반·시간표, 출결, 학생 운영 정보를 함께 보는 웹앱.
통합 클라우드 SSO로만 로그인한다. 학생·학원 없는 운영자는 안내만 본다.
학생 이름·학교·학년과 선생님 목록은 통합 클라우드에서 읽는다. 이 앱에서는 고치거나 DB에 복제하지 않는다.

## 실행

Node **24 LTS** 사용. Vite + React 19, node:http, node:sqlite, TypeScript, Vitest, oxlint.

```powershell
npm ci
Copy-Item .env.example .env
# .env의 로컬 클라우드 주소·앱 비밀값 채우기
npm run dev
```

기본 주소 `http://127.0.0.1:8476`, 태블릿 주소 `/kiosk`.
`npm run build` 후 `npm start`로 정적 파일과 API를 한 서버에서 실행한다.
개발 서버도 같은 `server/handler.ts`를 쓴다. API 코드를 고친 뒤에는 개발 서버를 다시 켠다.
클라우드 프로그램 관리에서 웹 프로그램 ID `mago-hagwon`, 주소를 이 로컬 주소로 등록한다.
별도 회원 가입·비밀번호 로그인·데모 로그인 우회는 없다.

## 환경 변수

| 이름 | 설명 |
| --- | --- |
| `MAGO_CLOUD_URL` | 클라우드 원점. 로컬 시험 `http://127.0.0.1:8475` |
| `MAGO_APP_ID` | 앱 ID. 기본 `mago-hagwon` |
| `MAGO_APP_SECRET` | 해당 앱 비밀값. 서버에서만 사용 |
| `DATA_DIR` | `hagwon.db`, `server.secret` 위치. 기본 `./data` |
| `SERVER_SECRET` | 선택 암호화/HMAC 비밀값. 비우면 데이터 폴더에 자동 생성. 변경 금지 |
| `HOST` / `PORT` | 기본 `127.0.0.1` / `8476` |
| `COOKIE_SECURE` | HTTPS 환경에서 `1`. Secure + `__Host-` 쿠키 사용 |
| `STATIC_DIR` | 선택. 빌드 정적 파일 위치, 기본 `dist` |

`npm start`는 `.env`를 읽는다. Vite는 서버에만 전체 환경 변수를 전달한다.
환경 변수를 클라이언트 번들에 넣지 않는다. 실제 로컬 실행용 `.env`는 gitignored이며 비밀값을 README나 예제에 적지 않는다.

## 사용 순서

1. 원장이 운영 설정에서 강의실을 넣는다.
2. 반·시간표에서 반 이름·계약 과목·담당 선생님·기간·반복 시간을 넣는다. 요일별 시각·강의실은 여러 개 가능.
3. 저장한 반의 **반 고치기**에서 학생·들어온 날을 골라 배정한다. 나간 날을 적으면 그날까지 수업에 포함한다.
4. 운영 설정의 **없는 번호 모두 만들기**로 학생 번호를 만든다. 발급 직후 창에서 한 번만 확인한다.
5. **태블릿 등록 번호 만들기** → 다른 브라우저의 `/kiosk`에서 6자리 번호를 넣는다. 10분 안에 한 번만 쓴다.
6. 학생은 숫자 4자리를 넣는다. 한국 날짜 기준 첫 입력은 등원, 다음은 하원. 연타 방지를 위해 같은 학생은 3초 간격.
7. 출결에서 반·날짜를 고른다. 태블릿 기록과 수동 출결을 구분해서 저장한다. 모두 출석으로 / 개별 상태 / 메모를 쓸 수 있다.
8. 휴강·보강은 반 고치기에서 지정한다. 휴강은 현재 기준 날짜의 수업 줄에서, 보강은 원하는 날짜·시간을 골라 한 번 추가한다.

## 데이터·권한

- 모든 DB 테이블에 `academy_id`가 있다. 운영 기록은 `(academy_id, kind, id)` 복합 키. SQL 조회·수정은 로그인에서 확인한 학원 ID로 한정한다. 사용자 입력 학원 ID를 믿지 않는다.
- `records`: 반, 날짜별 수업 예외, 학생 배정, 출결, 등하원, 학생 운영 정보, 강의실, 등록 코드, 태블릿, 기기별 실패 제한. `pins`: 학원 내 번호 HMAC 유일 제약. `sessions`: 앱 세션. 1차 소규모 운영을 위해 운영 기록은 종류별 JSON 행으로 저장한다.
- 원장은 모두 수정. 선생님은 반·학생을 읽고 **담당 수업 출결만** 수정한다. 오늘·출결 목록도 담당 반만 내려준다. 운영 설정·번호·배정·반 쓰기는 서버에서 403.
- SSO state는 HttpOnly 쿠키 + 서버의 10분 일회용 상태로 검사한다. 클라우드 코드 교환 후 `/api/me`를 확인하고 앱 자체 세션을 만든다. 클라우드 토큰은 AES-256-GCM으로 서버에만 저장한다. 앱 세션은 24시간, 클라우드는 최대 10분마다 재확인. 정지·로그아웃이면 세션 삭제. 재확인 연결 실패 시 요청은 실패하며 예전 권한으로 계속 진행하지 않는다.
- 학생 명단은 학원별 30초 캐시. 원장·선생님 요청에서 갱신할 때 `purged[]` 학생의 운영 정보·배정·출결·등하원·번호를 삭제한다. 소프트 삭제 학생은 숨기며 새 배정·번호 발급 불가. 태블릿 단독 사용 중에는 클라우드 명단을 직접 호출하지 않는다. 명단 변경 후 직원 화면을 새로 불러와 동기화한다.
- 태블릿 등록 때 해당 브라우저의 직원 앱 세션을 제거한다. 기기 토큰은 HttpOnly 쿠키, DB에는 SHA-256만. 태블릿 토큰으로는 일반 API를 사용할 수 없다. 기기를 끄면 즉시 차단한다. 최근 기록은 해당 기기의 시각·등하원만 보여 학생 이름·명단을 노출하지 않는다.
- 번호는 `HMAC-SHA256(서버 키, 학원 ID:번호)`만 저장한다. 4자리 번호는 일반 해시만으로 보호하기 어려우므로 키 기반 HMAC 사용. 평문·복호화용 사본을 보관하지 않는다. **번호 보기 없음, 잊으면 다시 만들기**. 일괄 발급은 번호 없는 학생만 처리한다. 재발급하면 예전 번호는 즉시 무효.
- 틀린 번호 5회 후 해당 기기만 1분 제한. 실패 제한은 DB에 있어 서버 재시작에도 유지. 등록 번호 입력에도 서버 제한 적용. 외부 알림 발송 없음. 등원·하원·수동 결석은 `notify.ts` 한 곳으로 연결한다.
- 날짜·시간은 Asia/Seoul. 등원 시각이 수업 시작 60분 전~끝 사이이면 자동 출석. 시작 10분 뒤까지 출석, 이후 지각. 이미 수동으로 정한 상태·메모는 바꾸지 않는다. 같은 날 여러 수업은 각각 계산한다.

## 로컬 시험

운영 서버·실제 계정은 사용하지 않는다. 다른 저장소의 파일·브랜치도 변경하지 않는다.

```powershell
npm run build
npm test
npm run lint

$testRoot = Join-Path $env:TEMP ('mago-hagwon-local-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory $testRoot
git -C C:\Users\구현민\Documents\Mago\MagoEdu archive --output="$testRoot\cloud.tar" origin/main server sdk
tar -xf "$testRoot\cloud.tar" -C $testRoot
Push-Location "$testRoot\server"
# 해당 origin/main에는 package-lock.json이 없다. 임시 복사본에서만 생성한다.
npm install --package-lock-only --no-audit --no-fund
npm ci --no-audit --no-fund
Pop-Location
node scripts/local-integration.mjs $testRoot
```

두 포트가 비어 있어야 한다. 스크립트는 실행마다 별도 `cloud-data-<임의값>`을 만들고, 클라우드를 `PORT=8475`, `LAUNCHER_REPO=`(빈 값), 임의 운영자 비밀번호로 실행한다. API로 학원·원장·선생님·학생 3명, 웹 프로그램·앱 비밀값을 만든다. 시험용 `.env`를 쓰므로 기존 `.env`가 있으면 임시 폴더의 `previous.env`로 보관한 뒤 교체한다.
앱은 8476에서 실행하고 실제 SSO authorize → callback → token 교환, 반 배정 → 태블릿 등록 → 번호 입력 → 자동 출석, 선생님 수동 출결·운영 설정 차단을 검증한다. 결과는 임시 폴더 `integration-result.json`. 비밀번호·학생 번호는 임시 `browser-fixture.json`에만 있다.
기본은 시험 끝에 두 서버를 모두 종료한다. 브라우저 수동 확인이 필요하면 `$env:KEEP_LOCAL_SERVERS='1'`을 설정한 뒤 실행하고, 확인 후 Ctrl+C로 종료한다. 재실행은 같은 임시 폴더에 새 클라우드 데이터를 만들며 앱 데이터도 실행별 분리한다.

Vitest는 실제 루프백 가짜 클라우드 HTTP 서버를 사용한다. 최대 작업자 2, 파일 병렬 실행 없음 (`vitest.config.ts`). SSO·역할·학원 간 분리·반복 수업·휴강·보강·자동 출석 경계·수동 보호·태블릿 등록 만료/재사용·기기 권한·번호 중복/실패 제한·purged를 검사한다.

## 기획에서 정한 점

- 별도 서버 방식은 이번 작업 지시를 따른다. 기획서의 통합 클라우드 내부 모듈 권고 대신 과목내비와 같은 구조.
- 재원 상태·등록일·퇴원일·출생 연도는 이번 지시에 따라 앱에 둔다. 이름·학교·학년은 클라우드 전용.
- 출생 연도만으로 정확한 만 나이를 알 수 없다. 올해 기준 나이가 **14 이하이면 ‘14세 미만 확인 필요’**라고 보수적으로 표시한다. 동의 판정 기능은 없음.
- 본문 14px, 주황 `#F76B15`, 회색 표·왼쪽 메뉴·학생 정보 창 탭. 지정 그림의 수납·알림·상담 등 2차 요소는 제외.
- 반 배정은 학생당 반별 한 기간을 기록한다. 같은 반 퇴반 후 재등록 시 기간을 덮어쓴다. 여러 재등록 이력은 2차에 별도 이력 행으로 확장할 일.
- 주간 표는 보이는 수업의 가장 이른 시작 시부터 가장 늦은 종료 시까지 앞뒤 한 시간 여유로 표시한다. 수업이 없으면 14~22시. 정확한 시작·끝은 수업 카드에 표시한다. 분 단위 높이 비례 표는 아님.

## 요청 IP
